# Экраны Qadam: структура, состояния, данные

Документ описывает экран до вёрстки. После вёрстки экран проверяется скриншотами Playwright
(светлая и тёмная темы, desktop 1440×900 и mobile 390×844) и дорабатывается по ним.

## Принципы

- **Характер**: светлый, воздушный, технологичный; акценты — небесно-голубой (primary) и золотой (gold)
  флага РК; орнамент «қошқар мүйіз» только фоном на 4–10 % непрозрачности в hero и сертификатах.
- **Типографика**: Inter — интерфейс; Geologica — hero, заголовки страниц и крупные числа
  (Unbounded и Manrope из ТЗ не содержат казахских букв, см. D-016). Шкала 12–60, числа — `tabular-nums`.
- **Цвет**: только токены (`bg-surface`, `text-fg-muted`, `bg-primary`…). Текст и кнопки с белой
  надписью — primary-700 (5,3:1); бренд-голубой #00A3C4 (primary-500) — декоративные элементы.
- **Глубина**: три уровня теней (sm — карточки, md — hover и поповеры, lg — модалки); в тёмной
  теме — границы и мягкое свечение.
- **Состояния**: у каждого экрана описаны загрузка (skeleton той же формы), пусто (иллюстрация +
  главное действие), ошибка (problem code → локализованный текст + «Повторить»), нет прав.
- **Адаптивность**: студенческие экраны mobile-first (от 360 px), дашборды руководства — от 768 px.
- **Доступность**: WCAG 2.2 AA, видимый фокус, клавиатура, подписи у всех контролов, `aria-live` для статусов.

## Layout-ы

| Layout            | Где                                     | Структура                                                                                                                                                                               |
| ----------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PublicLayout`    | лендинг, витрина, конкурсы, верификация | стеклянная шапка (лого, навигация, язык, тема, «Войти»/«Начать»), контент, футер; на мобильных — меню в шторке                                                                          |
| `AuthLayout`      | вход, регистрация, восстановление, OTP  | слева форма (max 384 px), справа бренд-панель (градиент primary-600→950, орнамент, ценностные тезисы)                                                                                   |
| `AppShell`        | кабинеты всех ролей                     | сворачиваемый сайдбар 256/72 px (секции по ролям, активный пункт — primary-soft), стеклянная шапка: заголовок/крошки, поиск ⌘K, уведомления, аватар; контент 1280 px (дашборды 1440 px) |
| `WorkspaceLayout` | рабочее пространство проекта            | 3 колонки: шаги (288 px) · форма (до 768 px) · AI-ментор (384 px, сворачивается в рейку 56 px); на телефоне шаги и ментор — шторки                                                      |

## Дизайн-система `/design`

Витрина токенов и компонентов (фаза 1). Шапка — `PublicLayout`; слева sticky-оглавление разделов
(на мобильных — горизонтальная лента якорей). Разделы: цвета (шкалы и семантика с живым расчётом
контраста), типографика (Geologica/Inter, казахский алфавит), форма и глубина (радиусы, тени,
отступы, движение), кнопки, формы, бейджи и аватары, карточки, оверлеи, обратная связь, навигация,
данные (KPI, gauge, таблица), пустые состояния (10 иллюстраций), layout-ы (живые демо
`/design/shell`, `/design/workspace`, `/design/auth`).

## 1. Лендинг (`/`, публичный)

- **Layout**: `PublicLayout`.
- **Hero**: заголовок Geologica 60/48 px («Идеядан нарыққа — бір қадам» / «От идеи до рынка — один шаг»),
  подзаголовок, CTA «Начать проект» (primary) и «Смотреть витрину» (secondary); справа —
  анимированная визуализация маршрута «идея → инкубатор → оценка → витрина → Demo Day → рынок»
  (SVG-путь с бегущими точками, 6 узлов-карточек; при reduced motion — статично).
- **Живые счётчики**: проекты, студенты в инкубаторе, проекты на витрине, победы — `AnimatedNumber`.
- **Как это работает**: 4 стадии инкубатора карточками с иконками и шагами.
- **Лучшие проекты**: 3–6 карточек витрины (обложка, название, отрасль, балл готовности).
- **Для кого**: три блока — студентам / вузам / партнёрам, у каждого CTA.
- **Финальный CTA** на градиенте с орнаментом; футер.
- **Данные**: `GET /public/stats`, `GET /showcase?featured=true`.
- **Состояния**: счётчики-скелетоны; при ошибке API блоки витрины скрываются без поломки страницы.

## 2. Дашборд студента (`/app`)

- **Layout**: `AppShell`.
- **Шапка**: приветствие по имени и времени суток, streak активности.
- **Карточка текущего проекта**: обложка, название, `StageTrack` 4 стадий, кольцо прогресса,
  «Следующий шаг» с кнопкой «Продолжить», последний AI-балл.
- **Колонка справа**: дедлайны конкурсов (ближайшие 3), ближайшая встреча с ментором.
- **Лента активности команды** (комментарии, изменения шагов, оценки) и **рекомендации AI** (2–3 карточки).
- **Пусто**: нет проекта → иллюстрация `idea`, «Создать первый проект», «Найти команду».
- **Данные**: `GET /me/dashboard`.

## 3. Рабочее пространство проекта (`/app/projects/:id/steps/:step`)

- **Layout**: `WorkspaceLayout`.
- **Шапка**: крошки (Проекты → Название → Стадия → Шаг), аватары команды онлайн (presence),
  индикатор «Сохранено · 2 сек назад» / «Сохраняем…» / «Нет сети», меню проекта.
- **Слева**: 4 стадии × шаги (`Stepper`), у стадии мини-прогресс; закрытые шаги — замок с объяснением.
- **Центр**: заголовок шага, подсказка-методика, структурированная форма (Tiptap для длинных полей),
  комментарии к полям (иконка у поля → тред), чек-лист «что усилить» от AI, кнопка «Завершить шаг».
- **Справа**: AI-ментор — чат со стримингом, режим «коуч/соавтор», «Применить в поле», источники RAG.
- **Состояния**: конфликт версий (диалог сравнения «ваша / на сервере»), офлайн, шаг закрыт.
- **Данные**: `GET/PUT /projects/:id/steps/:step` (ETag/If-Match), SSE ментора и присутствия.

## 4. Отчёт AI-оценки (`/app/projects/:id/evaluations/:evalId`)

- **Layout**: `AppShell`.
- **Hero отчёта**: `ScoreGauge` итогового балла, уровень готовности (badge), дата, модель и версия
  промпта, плашка «Оценка сгенерирована AI и носит рекомендательный характер».
- **Динамика**: дельта к прошлой оценке, мини-график истории.
- **Критерии**: radar-chart и список критериев с баллом, весом и обоснованием.
- **Red flags**: карточки по серьёзности (critical/high/medium). **Гипотезы**: 3–5 карточек.
- **Эксперименты на 7 дней**: чек-лист-таймлайн (что сделать, как измерить, критерий успеха).
- **Рекомендации** «что сделать в первую очередь»; правки эксперта видны с пометкой «изменено человеком».
- **Действия**: «Скачать PDF», «Запросить новую оценку».

## 5. Витрина (`/showcase`)

- **Layout**: `PublicLayout`.
- Заголовок и поиск (полнотекстовый, kk/ru/en); sticky-панель фильтров (отрасль, стадия, факультет,
  год, технология, «ищут инвестиции / команду / партнёра»); сетка карточек 3/2/1 колонки;
  быстрый просмотр в `Sheet` справа; бесконечная подгрузка («Показать ещё»).
- **Пусто/нет результатов**: иллюстрация `search`, «Сбросить фильтры».

## 6. Публичная страница проекта (`/showcase/:slug`)

- Журнальная вёрстка: hero с обложкой и видео-питчем; якорная навигация по секциям
  «Проблема → Решение → Рынок → Команда → Трекшн → Что нужно проекту»; крупная типографика,
  цитаты, цифры рынка; балл готовности (если команда разрешила); кнопка «Связаться с командой»
  (диалог с формой для партнёра). SEO: серверные meta, OG-картинка, JSON-LD.

## 7. Конкурс (`/competitions/:slug`, `/app/competitions/:id/manage`)

- **Публичная страница**: hero с призами и сроками этапов (таймлайн), требования, критерии, CTA «Подать заявку».
- **Форма подачи**: выбор проекта, автоподстановка данных инкубатора, проверка требований (чек-лист).
- **Админка организатора**: канбан заявок по статусам (подана → экспертиза → финал → победитель),
  назначение жюри, прогресс оценивания, лидерборд.

## 8. Экран жюри (`/app/jury/:competitionId`)

- Split-view: слева проект (вкладки: паспорт, питч, документы), справа рубрика со слайдерами
  0–10 и комментарием по критерию; горячие клавиши (J/K — проект, 1–0 — балл, Ctrl+Enter — отправить);
  автосохранение; прогресс «оценено 12 из 30».

## 9. Demo Day — режим проектора (`/demo-day/:sessionId/projector`)

- Тёмный полноэкранный режим 1920×1080: текущий выступающий, огромный таймер питча и Q&A,
  QR-код для голосования, живой график голосов, очередь выступлений; финальный экран победителей с конфетти.

## 10. Аналитика руководства (`/app/analytics`)

- **Layout**: `AppShell` (wide).
- KPI-плитки (6), воронка «идея → … → победа», сравнение факультетов, тепловая карта активности,
  лучшие проекты месяца, «застрявшие» проекты; фильтры периода и факультета; «Скачать отчёт для МНВО»
  (XLSX/PDF); AI-digest «Что произошло за месяц».

## 11. Верификация сертификата (`/verify/:code`)

- Минималистичная страница: крупный статус «Действителен» (success) или «Отозван» (danger),
  кому, за что, когда, кем выдан, проверка подписи Ed25519, ссылка на PDF.

## 12. Админка тенанта (`/app/admin`)

- Вкладки: брендинг (логотип, основной цвет с генерацией палитры и проверкой контраста, live-превью),
  AI-настройки (провайдер и модель по функциям, лимиты, расход токенов), пользователи и роли,
  факультеты, рубрики и шаблоны, аудит (фильтры, экспорт), API-ключи и вебхуки.

## Фаза 2: вход, онбординг, профиль, команда, администрирование

Экраны фазы 2 (скриншоты — `docs/design/screenshots/phase-2/`, светлая/тёмная тема, 1440 и 390 px).
Тексты — `locales/*/{landing,auth,onboarding,app,team,admin}.json`, ошибки API — `common:errors.<code>`.

### Лендинг v1 (`/`)

- Hero: заголовок, подзаголовок, CTA «Начать проект» (`/register`, для вошедших — «Перейти в кабинет»)
  и «Как это работает» (якорь). Справа — SVG-маршрут «идея → инкубатор → AI-оценка → витрина → Demo Day →
  рынок» (путь рисуется Motion, по нему бегут точки `animateMotion`; при reduced motion — статично);
  на телефоне — вертикальная лента этапов.
- «Как это работает»: 4 стадии с 14 шагами из ТЗ; три тезиса (AI-ментор, оценка по рубрике, витрина и Demo Day).
- Блоки «Студентам / Университетам / Партнёрам» (якоря в шапке), финальный CTA на градиенте с орнаментом.
- Футер: ссылки, бейдж состояния API `data-testid="api-version"` (проверка / версия / недоступен).
- Отложено до появления API: живые счётчики (`/public/stats`) и лучшие проекты витрины.

### Вход и регистрация (`AuthLayout`)

- `/login`: почта + пароль, «Забыли пароль?», «Войти по коду из письма», кнопки SSO тенанта
  (полная навигация на `/api/v1/auth/oidc/{id}/start?redirect=`), ссылка на регистрацию (если она открыта).
  `?error=<code>` (неудачный SSO: `auth.oidc_failed`, `auth.not_a_member`, `auth.account_suspended`) — красный callout.
- `/login/code`: шаг почты, затем 6 полей кода (вставка и автозаполнение `one-time-code`, автоотправка),
  повторная отправка через 60 с.
- `/register`: имя, почта (подсказка о доменах тенанта), пароль с индикатором надёжности, согласие на
  обработку ПДн (не отмечено по умолчанию, раскрывающийся текст и редакция) → `consent_version`.
  Закрытая регистрация — пустое состояние и SSO. Ошибки 409/422 — у полей.
- `/verify-email`, `/forgot-password` (всегда «проверьте почту»), `/reset-password` (`&invite=1` — «Создайте пароль»).
- Вошедшие на `/login` и `/register` уходят в `/app` (или `/onboarding`); `?redirect=` возвращает на исходную страницу.

### Онбординг (`/onboarding`, только до завершения)

- Фокус-экран: шапка с логотипом, языком, темой и «Выйти»; прогресс из 4 сегментов «Шаг N из 4 · название».
- Шаги в карточке со сдвигом и затуханием (Motion, направление по кнопке), фокус переходит на заголовок шага:
  1. язык (карточки kk/ru/en, интерфейс переключается сразу);
  2. учёба: факультет (обязателен, если структура загружена), кафедра, уровень и курс (пилюли, переносятся
     на телефоне), поиск группы с подстановкой факультета, уровня и курса; сотрудникам — только факультет и кафедра;
  3. направления (обязательно хотя бы одно) и навыки — теги с подсказками и своим вводом;
  4. «Есть ли идея?» — да (идея одним предложением, 10–500 символов) / пока нет (подсказка про доску команд).
- Валидация по шагам (`features/onboarding/steps.ts`), `PUT /me/onboarding`, конфетти и переход в `/app`.

### Кабинет (`AppShell`, `/app/*`)

- Навигация по ролям: Главная, Мой профиль, Ищу в команду; «Администрирование» — Участники
  (tenant_admin, innovation_manager) и Импорт данных (tenant_admin); «Настройки» — Безопасность.
  Внизу — меню пользователя (профиль, безопасность, выход). Заголовок страницы — в верхней панели;
  разделы кабинета есть в палитре ⌘K.
- **Главная** `/app`: приветствие по времени суток, роли, баннер «Подтвердите почту» с повторной отправкой,
  честная карточка «Инкубатор — скоро» со стадиями, свежие запросы в команды, прогресс профиля (кольцо и
  чек-лист из 7 пунктов), учёба и интересы, быстрые ссылки администратора.
- **Профиль** `/app/profile`: карточка с аватаром (JPEG/PNG/WebP/GIF до 10 МБ, проверка до загрузки),
  публичная ссылка (копировать/открыть); форма «О себе», навыки и интересы, ссылки, видимость и адрес
  профиля. Панель сохранения прилипает к низу только при несохранённых изменениях.
- **Публичный профиль** `/u/:slug` (`PublicLayout`, без входа): обложка, аватар, имя, «Ищет команду»,
  вуз и факультет, о себе, навыки, интересы, ссылки (только http/https). 404 — пустое состояние.
- **Ищу в команду** `/app/team`: вкладки «Все / Мои» (в адресе), поиск, роль и навык; карточки (автор,
  факультет, время, описание с «Показать полностью», роли, навыки, отклики); «Показать ещё» по курсору.
  Создание и редактирование — диалог (`?new=1` открывает сразу), отклик — диалог с предупреждением о
  передаче контактов. Пустые состояния: нет запросов / ничего не найдено / нет своих.
- **Запрос** `/app/team/:id` (письма ведут на `/team/:id` → сюда): карточка, для автора — отклики с почтой
  (mailto, копировать), закрыть/открыть набор, изменить.
- **Безопасность** `/app/settings/security`: активные сеансы (браузер и ОС из User-Agent, IP, вход,
  активность, «Это устройство»), завершение сеанса, «Выйти на других устройствах» с подтверждением;
  смена пароля с индикатором надёжности (другие сеансы завершаются сервером).

### Администрирование

- **Участники** `/app/admin/members`: поиск по имени и почте, фильтры роли и факультета, таблица (участник,
  роли, учёба, статус, активность), «Показать ещё». tenant_admin: меню строки — роли (диалог с
  чекбоксами и пояснениями; снять с себя администратора нельзя) и блокировка/разблокировка с подтверждением.
  innovation_manager видит список без действий.
- **Импорт** `/app/admin/import`: тип (студенты / структура), зона drag&drop (CSV или XLSX до 10 МБ,
  проверка расширения и размера до отправки), справка по столбцам и шаблоны
  (`/templates/students.csv`, `/templates/structure.csv`, UTF-8 с BOM, русские заголовки).
  Предпросмотр: сводка (всего, без ошибок, с ошибками, создать, обновить), таблица строк с подсветкой
  ошибочных ячеек и текстами ошибок, фильтр «Только строки с ошибками», постраничный показ по 100 строк;
  прилипающая панель «Импортировать N строк». Итог: создано, обновлено, пропущено, отправлено приглашений.

## Фаза 3: AI-слой

Экраны фазы 3 (скриншоты — `docs/design/screenshots/phase-3/`, светлая/тёмная тема, 1440 и 390 px).
Тексты — `locales/*/ai.json`, ошибки API — `common:errors.ai.*` и `common:errors.knowledge.*`.
В навигации «Администрирование»: «AI-настройки» и «Расход AI» (tenant_admin), «База знаний»
(tenant_admin, innovation_manager); руководство (leadership) видит только «Расход AI».

- **Предупреждение об AI** (`AiNotice`, данные — `GET /ai/status`): если хотя бы одна функция идёт к
  внешнему провайдеру — Callout «Данные отправляются внешнему AI-провайдеру; ИИН, телефоны и почта
  маскируются до отправки». Если у участника есть дневной лимит — полоса «Использовано N из M токенов,
  сбросится в 00:00» (при ≥ 90 % — предупреждающий тон). Локальная модель без лимита — компонент не
  показывается. Используется на AI-настройках и (фаза 4) в AI-менторе.
- **AI-настройки** `/app/admin/ai` (tenant_admin): сверху `AiNotice`. Карточка «Маршруты» — по строке на
  функцию (ментор, оценка, генерация, сводка, эмбеддинги): действующая цепочка провайдеров
  (своя или «По умолчанию» с бейджем), для каждого звена — выбор провайдера из настроенных
  (внешние помечены «внешний»; при «Только локальные модели» недоступны), поле модели с подсказкой
  модели по умолчанию, вверх/вниз/удалить; «Добавить резервный» (до 5 звеньев), «Сбросить к умолчанию».
  Кнопка «Проверить» у каждой функции открывает панель проверки: поток текста модели в реальном времени
  (SSE), затем провайдер, модель, версия промпта и токены, либо понятная ошибка; «Остановить» прерывает
  запрос. Карточка «Политика»: переключатель «Только локальные модели», режим ментора
  (Наставник — вопросы и подсказки / Соавтор — может предлагать готовые тексты), дневные лимиты токенов
  на участника и на вуз (0 — без лимита). Прилипающая панель «Сохранить» при изменениях; сохранение с
  `If-Match`, при 412 — сообщение «настройки изменил другой администратор» и перезагрузка.
- **Расход AI** `/app/admin/ai/usage` (tenant_admin, leadership): период 7 / 30 / 90 дней
  (SegmentedControl, в адресе `?days=`). Плитки: запросы, входные и выходные токены, стоимость (USD, с
  линией по дням). Таблицы: по функциям (запросы, токены, ошибки, стоимость), по моделям (провайдер,
  модель, запросы, токены, стоимость), по дням (с полосой относительного объёма). Пусто —
  EmptyState «AI ещё не использовали».
- **База знаний** `/app/admin/knowledge` (tenant_admin, innovation_manager): документы, из которых
  AI-ментор берёт ответы со ссылками на источник. Таблица (название, статус «Индексируется / Готов /
  Ошибка» с текстом ошибки, фрагментов, символов, добавлен, удалить), «Показать ещё» по курсору; пока
  есть документы в индексации — список обновляется каждые 3 с. «Добавить документ» — диалог: название и
  вкладки «Текст» / «Файл» (PDF, DOCX, TXT, MD до 20 МБ, проверка до отправки). Удаление — с
  подтверждением. Блок «Проверить поиск»: запрос → найденные фрагменты (документ, раздел, отрывок,
  релевантность в %). Пустое состояние с призывом добавить положение или регламент.

## Фаза 4: инкубатор

Экраны фазы 4 (скриншоты — `docs/design/screenshots/phase-4/`, светлая/тёмная тема, 1440 и 390 px).
Тексты интерфейса — `locales/*/incubator.json`; названия стадий, шагов, полей, подсказки и критерии
приходят из шаблона (`GET /incubator/template`, тексты на трёх языках). Ошибки — `common:errors.project.*`
и `common:errors.incubator.*`. В навигации всем участникам — «Проекты» (`/app/projects`) и в палитре ⌘K.

- **Проекты** `/app/projects` (`AppShell`): заголовок, «Новый проект»; у innovation manager, администратора
  и руководства — переключатель «Мои / Все проекты вуза» (в адресе `?scope=all`) и поиск по названию.
  Сетка карточек (`grid-cols-1`, от md — 2, от xl — 3): отрасль, название, слоган, аватары команды,
  полоса прогресса «N из 14 шагов», текущий шаг, бейдж «В архиве»; карточка ведёт в рабочее пространство.
  «Показать ещё» по курсору. Пусто — иллюстрация `projects` и «Создать первый проект».
  **Новый проект** — диалог: название (2–120), слоган (до 160, необязательно), отрасль (список),
  если у вуза есть политика интеллектуальной собственности — её текст в прокручиваемой области и
  обязательный чекбокс «Согласен» (передаётся версия политики). После создания — переход в проект.
- **Рабочее пространство** (`WorkspaceLayout` без отступов `AppShell`, во всю ширину):
  - *Шапка*: крошки «Проекты → Проект → Шаг», аватары тех, кто сейчас в проекте (присутствие, «+N»),
    статус сохранения в `aria-live`: «Сохраняем…», «Сохранено», «Нет сети — сохраним при подключении»,
    «Конфликт версий», «Ошибка сохранения». Кнопка «Команда и настройки».
  - *Слева*: кольцо общего прогресса, 4 стадии (заголовок и мини-прогресс), под каждой — шаги
    (`Stepper`): выполнен / одобрен руководителем (галочка), в работе (номер, «N из M полей»),
    не начат; число открытых комментариев. Сверху ссылка «Обзор проекта». На телефоне — шторка.
  - *Обзор* `/app/projects/:id`: название и слоган, стадии (`StageTrack`), «Продолжить: шаг N»,
    серия активных дней и бейджи (стадия пройдена, первая AI-проверка, материалы готовы, команда из
    трёх) с подсказками, вкладки «Активность» (лента: правки полей, комментарии, завершённые и
    одобренные шаги, новые участники) и «Материалы».
  - *Шаг* `/app/projects/:id/steps/:step`: «Шаг N из 14 · Стадия», заголовок, цель шага, чип методики,
    раскрывающийся блок «Что отличает сильный ответ» (критерии). Форма строится по типам полей:
    строка; текст с автоувеличением и счётчиком символов; число с группировкой разрядов и единицей
    (₸ или шт.); выбор; список (добавить, удалить, вверх/вниз); таблица (на телефоне — карточки строк,
    на десктопе — карточки в сетке колонок; добавить строку, удалить, переместить); ссылка.
    У каждого поля: метка, обязательность, подсказка, кнопки «Комментарии (N)» и «История».
    Шаг «Юнит-экономика» показывает расчёт маржи, LTV и LTV/CAC; шаг «Бизнес-модель» — схему Lean
    Canvas из ответов прошлых шагов (только чтение, со ссылками на шаги) и полей этого шага.
    Внизу — панель действий: «Проверить с AI», «Завершить шаг», у руководителя и innovation manager —
    «Одобрить» (диалог с обязательным комментарием); баннеры «Шаг завершён» / «Одобрен: комментарий»;
    «Следующий шаг». Чек-лист AI: итог, пункты ok / усилить / не хватает с советами, модель и версия
    промпта, пометка «Рекомендация AI». Ошибка завершения подсвечивает недостающие поля.
  - *Справа*: AI-ментор (на телефоне и до xl — шторка): `AiNotice` при внешнем провайдере, переключатель
    «Наставник / Соавтор» (если вуз разрешает оба), история (подгрузка ранних сообщений), потоковый
    ответ со «Стоп», лёгкая разметка (абзацы, списки, жирный), карточки предложений
    `<suggestion field>` с названием поля и «Применить в поле», чипы источников из базы знаний.
    Поле ввода: Enter — отправить, Shift+Enter — новая строка, до 4000 символов. Руководитель и
    менеджер видят диалог только для чтения.
- **Автосохранение**: через ~1,2 с после последней правки отправляются только изменённые поля с
  `If-Match`; поле, которое пользователь редактирует, не перезаписывается ответом сервера. При 412 —
  загрузка свежей версии и слияние по полям: без пересечений правок сохраняется автоматически, при
  пересечении — диалог «Конфликт версий» по каждому полю (ваша версия / версия на сервере, с
  разницей). Каждые 15 с (пока вкладка видна) отправляется присутствие; если шаг изменили другие, а
  своих несохранённых правок нет — шаг тихо обновляется.
- **История поля** — шторка: правки от новых к старым (автор, время, источник: правка / ментор /
  восстановление), разница по словам с предыдущим значением (добавленное — зелёным, удалённое —
  зачёркнуто), «Восстановить».
- **Комментарии** — шторка по шагу или полю: треды (ответы, «Решено» / «Открыть снова», правка и
  удаление своих), упоминания `@` из участников проекта.
- **Команда и настройки** — шторка: название, слоган, отрасль, «Скрывать чувствительные данные»;
  участники с ролями и должностями в команде, добавить участника или руководителя (поиск по вузу),
  удалить, выйти из проекта, передать владение (подтверждение), архивировать проект (подтверждение).
- **Материалы** — вкладка обзора и блок шага «Питч»: one-pager (PDF), питч-дек (PDF и PPTX), паспорт
  стартапа (PDF) на языке интерфейса; список со статусом (готовится — обновление каждые 3 с), скачать.
- **Главная** `/app` для студента: карточка текущего проекта (прогресс, стадии, «Продолжить: шаг N»),
  лента активности команды; без проекта — приглашение создать первый проект.
