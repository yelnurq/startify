# Ход работ

Отчёт по каждой фазе: что сделано, как проверено, что отложено и какие есть риски.

## Фаза 0. Фундамент — готово

**Сделано**
- Монорепозиторий `backend/` · `frontend/` · `deploy/` · `docs/`, `Makefile` (dev, down, logs,
  infra, migrate, run-*, gen, lint, test, e2e, build), `.env.example`, `CLAUDE.md`.
- Бэкенд (Go 1.26): конфиг из `QADAM_*` со строгой валидацией (неизвестная переменная — ошибка
  старта), slog JSON с атрибутами из контекста, пул pgx с транзакциями, задающими область RLS
  (тенант / system, savepoint'ы для вложенных), Valkey, RFC 9457 problem details с локализуемыми
  кодами, middleware (request-id, IP за доверенными прокси, recover, access-лог, security-заголовки,
  лимит тела, таймаут), Idempotency-Key на Postgres, `/healthz` `/readyz` `/metrics`,
  OpenTelemetry (OTLP по env), graceful shutdown.
- OpenAPI-first: `backend/api/openapi.yaml` (3.1) → oapi-codegen strict server (Go) и
  openapi-typescript (TS). Первый эндпоинт `GET /api/v1/meta`.
- База: goose-миграция фундамента (pgcrypto, citext, pg_trgm, pgvector, `uuid_generate_v7()`,
  функции RLS, роль `qadam_app`, `idempotency_keys`) + миграции River. sqlc — пакет на модуль.
- Worker на River с периодической очисткой просроченных ключей идемпотентности.
- Фронтенд: React 19, TS strict, Vite 8, TanStack Router (file-based, code splitting) и Query,
  Tailwind v4, i18next с ленивой загрузкой kk/ru/en и типизированными ключами, ESLint (strict
  type-checked + запрет литералов в JSX), Prettier, Vitest + MSW, Playwright.
- Docker Compose: postgres (pgvector), valkey, minio, gotenberg, clamav, mailpit, migrate, api,
  worker, web (Nginx: SPA + прокси `/api`, CSP, кэширование ассетов). Healthcheck'и у всех
  сервисов, где это возможно.
- CI (GitHub Actions): проверка актуальности сгенерированного кода → golangci-lint → тесты с
  `-race` → фронтенд (tsc, eslint, prettier, i18n, vitest, build) → e2e против compose → сборка образов.

**Проверено**
- `go test ./...`: юнит-тесты и интеграционные на testcontainers — изоляция тенантов через RLS
  (чтение, запись, обновление чужих строк), savepoint'ы и восстановление области, UUIDv7,
  хранилище идемпотентности, откат и повторное применение всех миграций, контрактный тест
  ответов API против `openapi.yaml`. Юнит-тесты с `-race` — в Linux-контейнере.
- golangci-lint (строгий набор из ~45 линтеров): 0 замечаний.
- Фронтенд: `tsc -b`, ESLint, Prettier, `i18n:check` (29 ключей × 3 языка), 11 тестов Vitest.
- `docker compose up` (эквивалент `make dev`): все сервисы healthy; через Nginx отдаются SPA,
  `/api/v1/meta` и problem+json для неизвестных путей.
- Playwright: 6 e2e-тестов (desktop 1440×900 и Pixel 7) против запущенного стека.
- Makefile проверен GNU make в Linux-контейнере (`make help`, dry-run целей).

**Отложено**
- Реальный прогон GitHub Actions — после push в удалённый репозиторий (локально выполнены те же шаги).
- Helm-чарт — фаза 12 (B-002).

**Риски**
- Репозиторий лежит в OneDrive: синхронизация `node_modules` и Docker-томов замедляет работу.
  Рекомендуется клонировать проект в каталог вне OneDrive.
- Образ MinIO берётся из сборки Chainguard (D-008); при смене политики Chainguard хранилище
  заменяется любым S3-совместимым сервером без изменений кода.

## Фаза 2. Аутентификация, тенанты, онбординг, профиль — готово

**Сделано**
- Контракт: 40 операций в `openapi.yaml` (вуз, вход и сессии, участник и профиль, файлы,
  структура вуза, доска «Ищу в команду», администрирование, импорт). Миграция `00002_identity`:
  18 таблиц, все таблицы с `tenant_id` под RLS (FORCE), журнал аудита только на добавление.
- Вуз по адресу: собственный домен → `<slug>.qadam.kz` → вуз по умолчанию; ссылки в письмах только
  на доверенные адреса (D-025).
- Вход: регистрация с согласием на обработку данных (D-023), пароль argon2id с политикой NIST
  (D-027), код из письма, SSO вуза по OIDC (PKCE, nonce, связывание только подтверждённой почты —
  D-024), подтверждение почты, восстановление и смена пароля, приглашения.
- Сессии: JWT на 15 минут и ротируемый refresh-токен в httpOnly cookie, обнаружение повторного
  использования refresh-токена, мгновенный отзыв (deny-list) и смена ролей (версия ролей) через
  Valkey, CSRF (Sec-Fetch-Site, Origin, double submit), список сессий и выход на других устройствах
  (D-022). Лимиты запросов рассчитаны на NAT кампуса, перебор останавливается по аккаунту (D-029).
- Онбординг в 4 шага (язык, учёба, интересы и навыки, идея), профиль с аватаром (обрезка, EXIF,
  JPEG без метаданных), публичная страница `/u/<адрес>` с транслитерацией казахских имён.
- Файлы: MinIO, проверка ClamAV, отдача через API с правами, ETag и кешированием, отложенное
  удаление (D-021).
- Доска «Ищу в команду»: запросы с ролями и навыками, поиск и фильтры, отклики с письмом автору,
  контакты видны только автору, оптимистичная блокировка ETag/If-Match (D-028).
- Администратор вуза: каталог участников, роли и блокировка; импорт структуры и студентов из
  CSV (UTF-8/Windows-1251) и XLSX с предпросмотром по строкам, приглашения (D-026). Шаблоны для
  скачивания в `frontend/public/templates/`.
- Письма на трёх языках через очередь River с зашифрованными данными; Mailpit в разработке.
- Лендинг, экраны входа и регистрации, онбординг, главная, профиль, доска, безопасность,
  участники, импорт — на трёх языках, в светлой и тёмной теме, на телефоне.
- `make seed`: КазУТБ с 4 факультетами, 10 кафедрами и 21 группой, 60 студентов, 8 менторов,
  6 членов жюри, innovation manager, руководство, администратор, запросы на доске; второй вуз
  `sandbox` для проверки изоляции. Демо-аккаунты — в README.

**Проверено**
- Go: 90 тестов (юнит и интеграционные на PostgreSQL в testcontainers), в том числе сквозные
  сценарии через HTTP с проверкой ответов по `openapi.yaml`: регистрация → письмо → онбординг →
  профиль → аватар; ротация и кража refresh-токена; код и восстановление пароля; CSRF; изоляция
  вузов (сессии, профили, структура, доска) и RLS по всем 13 таблицам тенантов; администрирование
  и импорт; SSO против mock-провайдера OIDC; перебор пароля. `-race` в Linux-контейнере — без гонок.
  golangci-lint — 0 замечаний.
- Frontend: 42 юнит-теста, `tsc` strict, ESLint, Prettier, `i18n:check` — 1124 ключа × 3 языка.
- E2E: 56 сценариев Playwright (desktop и телефон) против реального стека с чтением писем из
  Mailpit — и против Vite, и против production-сборки в Nginx с CSP.
- Визуально: 60 скриншотов (`docs/design/screenshots/phase-2/`); по ним исправлены перекрытия на
  лендинге, шапка публичного профиля, обрезка кнопок на телефоне, липкие панели, предпросмотр
  импорта (понятные названия столбцов и ошибок, карточки на телефоне), приветствие по имени.
- Найдено и исправлено при проверке на стеке: Nginx не перечитывал адрес API после пересоздания
  контейнера (502) — теперь адрес разрешается заново.

**Отложено**
- Оптимизация бандла (B-010), «Войти» в мобильной шапке публичных страниц (B-011), живые данные
  на лендинге (B-012) — фаза 6. Настройки вуза и SSO в интерфейсе (B-008), 2FA для
  администраторов (B-009), большие импорты фоном (B-007), сверка «осиротевших» объектов S3 (B-006).
- DAST-сканирование HawkScan не выполнялось: в окружении нет `hawk` CLI и ключа `HAWK_API_KEY`.

**Риски**
- При отказе Valkey аутентифицированные запросы получают 503 (проверка отзыва закрывается, а не
  пропускает) — Valkey нужно мониторить как обязательную зависимость.
- Аватары публичны по неугадываемому id (D-021): если вуз потребует закрытые фото, понадобится
  видимость `tenant`.

## Фаза 3. AI-слой — готово

**Сделано**
- Интерфейс `llm.Provider` и три провайдера: Anthropic (официальный Go SDK, Messages API,
  structured output, effort, кеширование системного промпта, серверные резервные модели для Opus),
  OpenAI-совместимый (vLLM, Ollama, LM Studio, OpenAI) и детерминированный mock, на котором демо
  работает без ключей и интернета. Стриминг, эмбеддинги, JSON Schema.
- `ai.Gateway` — единственный путь к моделям: маршруты по функциям (ментор, оценка, генерация,
  сводки, эмбеддинги) из настроек вуза, `QADAM_AI_ROUTES` или `QADAM_AI_DEFAULT`, цепочка
  резервных провайдеров, проверка ответа по схеме с одной попыткой исправления, режим «только
  локальные модели» (D-031). Переключение провайдера — переменной окружения, без изменения кода.
- Учёт каждого вызова (`ai_usage`: токены, кеш, стоимость, задержка, версия промпта, статус),
  дневные лимиты на пользователя и вуз со сбросом в 00:00 по Алматы и понятным сообщением (D-034).
- Маскирование ИИН (с контрольной суммой), телефонов и почты перед внешними провайдерами и
  обратная подстановка, в том числе в потоке (D-032); предупреждение в интерфейсе.
- Промпты — версионируемые шаблоны `internal/ai/prompts/*.tmpl`, данные пользователя только внутри
  тегов, защита от подмены инструкций (D-033).
- База знаний вуза: PDF, DOCX, TXT, Markdown или текст → фрагменты → pgvector; поиск по смыслу с
  запасным полнотекстовым, ежечасная переиндексация при смене модели эмбеддингов (D-030). В
  `make seed` — четыре демо-документа КазУТБ (положение о конкурсе, правила грантов, гид по
  интеллектуальной собственности, методичка по интервью).
- Экраны администратора: «AI» (маршруты и модели по функциям, резервные цепочки, только локальные
  модели, лимиты, режим ментора, проверка подключения с потоковым ответом), «Расход AI» (по
  функциям, моделям и дням; доступен и руководству), «База знаний» (загрузка, статус индексации,
  проверка поиска, удаление). Компонент `AiNotice` — предупреждение о внешнем провайдере и лимит.

**Проверено**
- Go: 119 тестов. Юнит-тесты провайдеров против фейковых серверов Anthropic и OpenAI (форма
  запроса, резервные модели, отказ, ошибки, поток), схем, маскирования, промптов, маршрутов;
  интеграционные — резервная цепочка и учёт, исправление ответа по схеме, данные не уходят наружу,
  режим «только локальные», дневной лимит с часовым поясом, отмена потока, настройки с ETag, SSE
  проверки подключения, база знаний (загрузка, индексация, поиск, изоляция вузов, переиндексация),
  поиск по демо-документам. `-race` в Linux-контейнере — без гонок. golangci-lint — 0 замечаний.
- Frontend: 60 юнит-тестов (парсер SSE, цепочки маршрутов, сообщения об ошибках), `tsc`, ESLint,
  Prettier, `i18n:check` — 1278 ключей × 3 языка.
- E2E: 68 сценариев Playwright зелёные (проверка подключения через Nginx, конфликт настроек 412,
  резервная цепочка, база знаний от загрузки до поиска, axe в светлой и тёмной теме, доступ
  руководства).
- Визуально: 28 скриншотов (`docs/design/screenshots/phase-3/`); по ним исправлены обрезанные
  таблицы расхода на телефоне, колонки базы знаний, отступы секций настроек.

**Отложено**
- ANN-индекс для базы знаний (B-013), OCR сканов (B-014), маскирование имён (B-015), кнопка
  переиндексации (B-016).
- DAST-сканирование HawkScan не выполнялось: нет ключа `HAWK_API_KEY`.

**Риски**
- Демо-эмбеддинги (mock) — мешок слов: поиск находит нужный раздел среди первых трёх, но
  релевантность низкая; для реального вуза нужна модель эмбеддингов (например, bge-m3 в Ollama).
- OneDrive превращает файлы репозитория в reparse points, и Go 1.23+ их пропускает («no Go source
  files»); на машинах разработчиков репозиторий лучше держать вне облачных папок.
