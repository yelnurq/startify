# Вход через Active Directory или LDAP: инструкция для администратора вуза

После настройки студенты и сотрудники входят в Qadam тем же логином и паролем, что и в почту,
Moodle или компьютеры университета. Пароли остаются в каталоге вуза: Qadam их не хранит, а только
проверяет при входе. Вход по почте и по коду из письма продолжает работать.

Всё настраивается на странице **Администрирование → Вход через каталог** (`/app/admin/directory`)
под учётной записью администратора вуза. SQL, файлы конфигурации и помощь разработчиков не нужны.

## 1. Что запросить у IT-отдела

Передайте IT-отделу этот список — обычно его выполняют за один день.

1. **Адрес контроллера домена** — именем, а не IP-адресом (например, `dc01.kazutb.local`),
   лучше два контроллера для резерва. Порт **636** (LDAPS) или **389** с поддержкой StartTLS.
2. **Сертификат центра сертификации**, которым подписан сертификат контроллера, в формате PEM
   (текст между `-----BEGIN CERTIFICATE-----` и `-----END CERTIFICATE-----`). На сервере центра
   сертификации: `certutil -ca.cert ca.cer`, затем `certutil -encode ca.cer ca.pem`. Если
   сертификат контроллера выдан публичным центром, этот пункт не нужен.
3. **Сервисную учётную запись только для чтения**, например `qadam-svc`: обычный пользователь домена,
   без прав администратора и входа на компьютеры, с паролем без срока действия (или с напоминанием
   о смене). Нужен её **DN**: `CN=qadam-svc,OU=Service Accounts,DC=kazutb,DC=local`.
4. **Где искать пользователей** — DN подразделения (OU) или корня домена, например
   `OU=Students,DC=kazutb,DC=local` или `DC=kazutb,DC=local` (поиск идёт по всем вложенным OU).
5. **DN групп для ролей Qadam** — например, «Администраторы Qadam», «Офис коммерциализации»,
   «Преподаватели», и, если нужно, группа всех, кому разрешён вход.
6. **Сетевой доступ** от сервера Qadam к контроллеру домена на порт 636 (или 389).
7. Убедитесь, что у пользователей заполнен атрибут **mail** — адрес на домене университета.

DN удобно узнать в PowerShell на любом компьютере домена:

```powershell
Get-ADDomain | Select-Object DistinguishedName
Get-ADUser qadam-svc | Select-Object DistinguishedName
Get-ADGroup "Qadam Admins" | Select-Object DistinguishedName
Get-ADUser ivanov.a -Properties mail, memberOf | Select-Object DistinguishedName, mail, memberOf
```

## 2. Заполнение страницы

Карточки страницы идут в том же порядке, что и шаги ниже. В подсказках у полей есть примеры.

1. **Тип каталога.** Выберите *Active Directory* (или OpenLDAP, FreeIPA). Фильтр поиска и атрибуты
   заполнятся типичными значениями — для Active Directory их обычно менять не нужно.
2. **Подключение.**
   - *Адрес сервера:* `ldaps://dc01.kazutb.local:636`. Несколько адресов через пробел —
     резервные: если первый недоступен, Qadam пробует следующий.
   - *StartTLS* включайте, только если используете `ldap://…:389`.
   - *Сертификат центра сертификации:* вставьте текст PEM из пункта 2 списка.
   - Соединение без шифрования (`ldap://` без StartTLS) допускается только на тестовой установке:
     пароли студентов шли бы по сети открытым текстом, поэтому в продакшне Qadam такие настройки
     не сохраняет.
3. **Сервисная учётная запись.** DN и пароль из пункта 3. Пароль хранится зашифрованным и больше
   никогда не показывается; чтобы его не менять, оставляйте поле пустым.
4. **Поиск пользователей.** База поиска из пункта 4. Фильтр должен содержать `{username}` — на его
   место подставляется логин, который ввёл человек. Блок «Атрибуты» открывайте, только если IT-отдел
   использует нестандартные атрибуты.
5. **Роли.** Добавьте строки «DN группы → роль». Кто не входит ни в одну группу, получает роль по
   умолчанию (обычно «Студент»). *Обязательная группа* пускает только своих участников.
   *Создавать аккаунты при первом входе* — включено: новые студенты получают аккаунт сами.
   *Обновлять роли при каждом входе* приводит роли из таблицы к группам каталога (роли, выданные
   вручную и не упомянутые в таблице, не меняются; последний администратор вуза роль не теряет).
6. **Страница входа.** Название вкладки на трёх языках, например «Учётная запись КазУТБ», и
   подсказка к логину: «Логин как в Outlook: ivanov.a». Пустые поля — текст по умолчанию.

Студенты Active Directory могут вводить логин как `ivanov.a`, `KAZUTB\ivanov.a` или
`ivanov.a@kazutb.local` — Qadam приведёт его к `ivanov.a`.

## 3. Проверка

1. Нажмите **«Проверить подключение»**. Проверка идёт по настройкам формы, даже несохранённым, и
   показывает каждый шаг: подключение, шифрование (кем выдан сертификат и до какого числа он
   действует), вход сервисной учётной записи, поиск в базе и сведения о сервере. Если в разделах
   каталога виден ваш домен, кнопкой «Подставить в базу поиска» его можно перенести в форму.
2. Нажмите **«Проверить пользователя»** и введите логин знакомого студента или сотрудника — пароль
   не нужен. Вы увидите его DN, почту, имя, группы, роли, которые он получит в Qadam, и будет ли
   разрешён вход: аккаунт уже связан, будет связан существующий аккаунт с той же почтой или будет
   создан новый. Проверьте и сотрудника из группы администраторов.

## 4. Включение

Переключатель **«Включить вход через каталог»** становится доступен после успешной проверки
подключения с текущими настройками. Включите его и нажмите **«Сохранить»**. На странице входа
появится вкладка университета — первой, а вход по почте останется рядом.

Если позже меняется соединение (адрес, сертификат, сервисная учётная запись или база поиска),
проверьте подключение ещё раз — иначе изменения не сохранятся. Отключить вход можно тем же
переключателем в любой момент: аккаунты и данные студентов сохраняются.

## 5. Частые ошибки

| Что показывает проверка | Причина | Что сделать |
|---|---|---|
| Имя сервера не найдено в DNS | Сервер Qadam не знает имени контроллера | Укажите полное имя (FQDN) или попросите IT-отдел добавить DNS-запись |
| Сервер отказал в подключении | Неверный порт или служба не слушает его | 636 для `ldaps://`, 389 для `ldap://`; проверьте службу на контроллере |
| Сервер не ответил вовремя | Межсетевой экран не пропускает Qadam | Откройте порт от сервера Qadam к контроллеру |
| Qadam не доверяет сертификату сервера | Сертификат выдан центром сертификации университета | Вставьте сертификат центра (PEM) в поле «Сертификат центра сертификации» |
| Сертификат выдан на другое имя | В адресе указан IP или другое имя | Укажите имя из сертификата, например `dc01.kazutb.local` |
| Срок действия сертификата истёк / скоро истекает | Сертификат контроллера просрочен | Попросите IT-отдел обновить сертификат |
| Неверный DN или пароль сервисной учётной записи | Опечатка или пароль сменился | Сверьте DN в PowerShell, введите пароль заново |
| Сервер требует шифрование | В домене включена обязательная подпись LDAP | Используйте `ldaps://` или StartTLS |
| Такого раздела нет в каталоге | Ошибка в базе поиска | Скопируйте DN из PowerShell или из «Разделов каталога» |
| Фильтр не нашёл ни одного пользователя | Фильтр или база не та | Верните фильтр типа каталога, проверьте базу |
| Логину соответствует несколько записей | Один логин в двух местах базы | Сузьте базу поиска или фильтр |
| В каталоге у пользователя нет почты | Не заполнен атрибут `mail` | Заполните почту в каталоге (или укажите другой атрибут почты) |
| Аккаунт принадлежит другому университету | Почта уже занята аккаунтом другого вуза | Человек входит в этот вуз паролем или кодом из письма; привязать чужой аккаунт нельзя |
| Почта не на домене университета | Адрес из каталога не на почтовых доменах вуза | Аккаунт создастся с неподтверждённым адресом; лучше хранить в каталоге адреса домена вуза |

Студенты при ошибках видят понятные сообщения: «Неверный логин или пароль», «Срок действия пароля
истёк — смените пароль в системах университета», «Учётная запись университета отключена»,
«Каталог университета сейчас не отвечает — войдите по почте».

## 6. Безопасность

- Соединение всегда зашифровано (LDAPS или StartTLS) с проверкой сертификата и имени сервера;
  отключить проверку нельзя.
- Пароли студентов не сохраняются; пустой пароль Qadam не отправляет в каталог вовсе (Active
  Directory принял бы его как анонимный вход).
- После 5 неудачных попыток за 15 минут логин временно блокируется в Qadam — раньше, чем
  срабатывает обычная блокировка Active Directory, поэтому Qadam сам не блокирует учётные записи
  вуза. Неудачные входы и изменения настроек пишутся в журнал аудита (без паролей).
- Отключение учётной записи в Active Directory закрывает новые входы. Уже открытую сессию
  завершите блокировкой участника на странице «Участники».
